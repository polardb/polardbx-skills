# Plan Metadata

EXPLAIN output may include metadata lines at the end (from `ExplainExecutorUtil#handleExplain`). These lines **are not part of the operator tree**, are not included in line numbering, and are interpreted separately in a `## Plan Metadata` section after the operator analysis table.

## Metadata Field Overview

| Field | Meaning | Appearance Condition |
|-------|---------|---------------------|
| `HitCache:<true\|false>` | Whether Plan Cache was hit | Always output |
| `Source:<source>` | Plan source (`PlanManager.PLAN_SOURCE` enum) | Always output |
| `TemplateId: <hex>` | SQL template ID (fingerprint of parameterized SQL) | Always output |
| `WorkloadType: <AP\|TP>` | Workload type | EXPLAIN COST only |
| `BaselineInfo Id: <id>` | SPM baseline ID | When BaselineInfo exists |
| `PlanInfo Id: <id>` | SPM plan ID | When PlanInfo exists |
| `baseline is rebuildAtLoad:<bool>` | Whether baseline is rebuilt at load time | When rebuildAtLoad |
| `baseline use post planner:<bool>` | Whether post planner is used | When rebuildAtLoad |
| `baseline hint:<hint>` | Hint bound to the baseline | When rebuildAtLoad |
| `PlanInfo fixed: <bool>` | Whether the plan is fixed (evolution locked) | BASELINE mode |
| `PlanInfo accepted: <bool>` | Whether the plan is accepted | BASELINE mode |
| `PlanInfo chooseCount: <n>` | Number of times the plan was chosen | BASELINE mode |
| `PlanInfo origin: <origin>` | Plan origin identifier | BASELINE mode |
| `cache node:` + digest line | Cached subquery node | When cache node exists |
| `extremely slow for multi nested subqueries` | Deeply nested subquery warning | When nesting depth is excessive |

## Source Enum Values (`PlanManager.PLAN_SOURCE`)

| Value | Meaning |
|-------|---------|
| `PLAN_CACHE` | Hit Plan Cache, using cached plan directly |
| `SPM_FIX` | SPM baseline fixed plan |
| `SPM_FIX_GRAY` | SPM baseline fixed plan (grayscale) |
| `SPM_PQO` | Plan selected by SPM Parameterized Query Optimization |
| `SPM_ACCEPT` | SPM accepted plan |
| `SPM_UNACCEPTED` | SPM unaccepted plan (under evolution) |
| `SPM_NEW_BUILD` | SPM newly built plan |
| `SPM_FIX_PLAN_UPDATE_FOR_ROW_TYPE` | SPM fixed plan updated due to RowType change |
| `SPM_FIX_PLAN_UPDATE_FOR_INVALID` | SPM fixed plan updated due to invalidation |
| `SPM_FIX_DDL_HASHCODE_UPDATE` | SPM fixed plan updated due to DDL table hashcode change |
| `DEEP_PAGE_OPTIMIZER` | Plan generated by deep pagination optimizer |

> To determine if it is an SPM plan: all sources except `PLAN_CACHE` and `DEEP_PAGE_OPTIMIZER` are SPM-sourced.

## Output Format

When EXPLAIN output contains metadata, add a section after the operator analysis table:

```
## Plan Metadata

| Field | Value | Description |
|-------|-------|-------------|
| HitCache | false | Plan Cache not hit, first compilation |
| Source | PLAN_CACHE | Plan source is cache |
| TemplateId | 57a15c50 | SQL template fingerprint |
```

## Interpretation Guidelines

- **HitCache:true + Source:PLAN_CACHE** — Plan hit cache, no optimization performed in this execution
- **HitCache:false + Source:PLAN_CACHE** — Optimization was performed but the cached plan was ultimately selected
- **Source:SPM_FIX** — Plan is fixed by SPM baseline, will not be replaced by evolution
- **Source:SPM_ACCEPT** — Plan selected from an SPM accepted baseline plan
- **Source:SPM_PQO** — Plan selected by Parameterized Query Optimization (PQO) based on parameter characteristics
- **Source:SPM_NEW_BUILD** — Newly built SPM plan, not yet accepted
- **Source:DEEP_PAGE_OPTIMIZER** — Plan rewritten by the deep pagination optimizer
- **BaselineInfo + PlanInfo** — Indicates the SQL is managed by SPM; check fixed/accepted status to determine if the plan is evolution-locked
- **cache node** — Indicates the plan contains cached subquery intermediate result nodes (LogicalCorrelate scenario)
- **extremely slow for multi nested subqueries** — Subquery nesting depth is excessive, execution may be extremely slow
